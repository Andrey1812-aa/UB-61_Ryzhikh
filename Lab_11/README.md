## Структура лабораторной работы

В данной лабораторной работе (`Lab_11`) представлены следующие файлы:

1. `analysis.py` — функции `validate_todos`, `completion_counts`, `top_users`, `leader_tasks` и `select_tasks`.
2. `main.py` — чтение JSON, ввод параметров, анализ задач и запись результатов.
3. `test_analysis.py` — автоматические проверки функций и сохранения JSON.
4. `todos.json` — исходные задачи.
5. `leaders.json` — выполненные задачи лидеров.
6. `selected.json` — задачи индивидуального варианта.
7. `fetch_profile.py` — получение профиля GitHub по HTTP.
8. `profile_sample.json` — локальный пример профиля.
9. `read_profile_sample.py` — чтение локального примера.

## Инструкция по запуску программ

Для запуска необходим Python 3 (рекомендуется версия 3.13 или новее).

1. Откройте терминал в папке `Lab_11`.

2. Запустите автоматические тесты:

   ```bash
   python test_analysis.py
   ```

3. Запустите основную программу:

   ```bash
   python main.py
   ```

(В Windows вместо `python` можно использовать `py`, а в некоторых системах — `python3`.)

В `main.py` введите ID пользователя `5` и подстроку `и`. Результаты будут записаны в `leaders.json` и `selected.json`. Для сетевого задания запустите `python fetch_profile.py`, а для локального примера — `python read_profile_sample.py`. При проверке сетевой запрос был недоступен, поэтому проверен локальный режим.

## Дополнительные объяснения и ответы на вопросы

- **Что такое JSON:** Это текстовый формат хранения и передачи данных. В этой работе массив JSON превращается в список словарей Python.

- **Чем отличаются load и dump:** `json.load` читает данные из файла, а `json.dump` записывает их. Варианты `loads` и `dumps` работают со строками.

- **Зачем проверять типы полей:** Каждая задача должна содержать целые положительные ID, название и логический признак выполнения. Проверка `type(value) is int` не принимает True и False вместо чисел.

- **Как определяются лидеры:** Сначала подсчитываются выполненные задачи каждого пользователя. Затем выбираются пользователи с максимальным положительным количеством выполненных задач.

- **Как выполняется индивидуальный вариант №8:** Функция `select_tasks` сравнивает ID пользователя и проверяет наличие подстроки в названии. Регистр не учитывается, поэтому и и И дают одинаковый результат.

- **Что такое HTTP-запрос GET:** Он используется для получения ресурса с сервера. В программе запрашивается профиль пользователя GitHub; `timeout` ограничивает время ожидания.

- **Чем отличаются HTTPError и URLError:** Первая ошибка связана с ответом HTTP, например отсутствием ресурса, вторая — с проблемой соединения. Для проверки без сети используется локальный пример.

- **Почему JSONDecodeError обрабатывается отдельно:** Это ошибка синтаксиса JSON и подкласс ValueError. Поэтому её нужно перехватывать раньше общей ошибки значения.
