## Дополнительные объяснения и ответы на вопросы

* **Почему таблица 2×3 важна при проверке:**
Она помогает заметить ошибку, когда в программе перепутаны количество строк и количество столбцов. В квадратной таблице они совпадают, поэтому неправильный цикл может случайно дать верный результат. На таблице из двух строк и трёх столбцов такая ошибка сразу становится заметной.

* **Чем отличаются индексы строки и столбца:**
В выражении `matrix[row][column]` сначала указывается номер строки, а потом номер элемента внутри неё, то есть столбца. Нумерация начинается с нуля. Например, в `[[1,2,3],[4,5,6]]` выражение `matrix[1][0]` даёт `4`.

* **Почему нельзя создавать таблицу через `[[0] * columns] * rows`:**
Так получается несколько ссылок на одну и ту же внутреннюю строку. Если изменить элемент в первой строке, этот же элемент поменяется и во всех остальных. Поэтому отдельные строки нужно создавать независимо, например обычным циклом `for`.

* **Чем отличается копирование внешнего списка от копирования строк:**
`matrix.copy()` создаёт новый внешний список, но внутренние строки остаются теми же объектами. Из-за этого изменение числа внутри копии может изменить исходную таблицу. Поэтому в тесте мы создаём пустой список и обычным циклом `for` добавляем в него копии строк с помощью `row.copy()`. Для нашей таблицы целых чисел этого достаточно.

* **Как считается сумма столбцов:**
Для каждого индекса столбца создаётся отдельная сумма `total`. Внутренний цикл проходит по всем строкам и добавляет элемент с этим индексом. Полученная сумма записывается в итоговый список. Для пустой матрицы функция сразу возвращает `[]`.

* **Как строится диагональный узор:**
Вложенные циклы перебирают строки и столбцы квадратной таблицы. Если индексы равны, записывается `0`. Если индекс строки меньше индекса столбца, записывается `1` (выше диагонали). Во всех остальных случаях записывается `2` (ниже диагонали).

* **Как выполняется индивидуальный вариант №8:**
Функция `transform` для каждой исходной строки создаёт новый список. Если число отрицательное (`number < 0`), оно уменьшается ещё на два: например, `-5` становится `-7`. Нули и положительные числа остаются прежними. В результате получается новая таблица того же размера, а исходная не изменяется.

* **Почему проверяется изменение результата после `transform`:**
Недостаточно проверить только правильность чисел. Если возвращаемая таблица использует исходные строки, то изменение одного элемента результата может испортить исходные данные. В тесте элемент результата намеренно меняется на `100`, после чего проверяется, что исходная таблица осталась такой же.

* **Как работает рекурсия в дополнительном задании:**
Рекурсивный факториал вызывает сам себя с аргументом на единицу меньше, пока не получит `0`. Это базовый случай, для которого ответ равен `1`. Для `factorial(3)` вызовы идут с числами `3 → 2 → 1 → 0`, затем результаты возвращаются как `1 → 1 → 2 → 6`. Обычная версия вычисляет тот же результат циклом. Для чисел от 0 до 20 результаты обеих функций сверяются с помощью `assert`.
